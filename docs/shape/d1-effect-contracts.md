## 1. Fresh-D1 schema constraints

### 1.1 Dialect mapping (pg → sqlite/D1) — per column family

| Postgres column | D1 replacement | Notes |
|---|---|---|
| `uuid` PK `defaultRandom()` | `text` PK; **value generated by an Effect ID layer** | Do not rely on SQLite `uuid()`; IDs come from a `Random`/UUID Effect layer (locked design: clock/ID layers). Stable across the row's life — media `storageKey` embeds the same UUID. |
| `timestamp with time zone` | `integer` unix **milliseconds** (drizzle `timestamp(..., { mode: 'timestamp_ms' })`) | All serializers call `.toISOString()`; keep that contract by converting `number → Date` at the row→API boundary. `occurredAt` etc. are compared numerically. |
| `date` (`relationship_start_date`) | `text` `'YYYY-MM-DD'` (drizzle `text`) | Route already validates `^\d{4}-\d{2}-\d{2}$`. API returns the raw string today — unchanged. |
| `jsonb` (`reminder_minutes_before`, `label`, `destination`) | `text(..., { mode: 'json' })` | Serialization must be stable: `number[]`, `{preset,customText?}`, `{name,lat,lon,radiusMeters}`. Round-trip exactly — `reminderMinutesBefore` is `undefined` vs `null`-sensitive at the API edge. |
| `double precision` (lat/lon/accuracy) | `real` (or `integer` with scale) — **pick `real` and keep full JS doubles via drizzle `mode: 'number'`** | Latitude/longitude are sent through untouched to the API; must not lose precision through the round trip. D1 `REAL` is a 64-bit float — matches PG `double precision`. |
| `boolean` | `integer 0/1` (drizzle `integer({ mode: 'boolean' })`) | |
| `text` enum-constrained | `text` + `check(...)` | All `check` constraints must be re-declared (see 1.3). |
| `size_bytes` as `text` (PG workaround for bigint/JS precision) | `integer` | Fresh D1 has no legacy data. Max admitted value is 100 MB (`100*1024*1024`) — far inside SQLite 64-bit `INTEGER`. Drop the text workaround. |

### 1.2 Tables (19) and per-table constraints to carry over

Reference `packages/api/src/db/schema.ts`; the list below records the
uniqueness/index/check set that must exist on D1, plus the fresh-D1
additions.

1. `users` — `email` unique (nullable; SQLite unique allows many NULLs —
   matches PG semantics). Keep `deleted_at` soft-delete.
2. `auth_accounts` — unique `(provider, provider_subject)`; `provider ∈
   {apple, google}`.
3. `user_sessions` — partial index `(user_id, expires_at) WHERE revoked_at
   IS NULL` (SQLite supports partial indexes on D1).
4. `spaces` — `archived_at` retained.
5. `space_members` — PK `(space_id, user_id)`; index `(user_id, state)`;
   **new partial unique indexes** (see 1.4): `(user_id) WHERE state='active'`
   and `(space_id) WHERE state='active' AND role='partner'`.
6. `space_invites` — unique `(code_normalized)`; `redeemed_at`/`expires_at`
   retained (guarded redeem, see §5).
7. `imported_milestones` — partial index `(space_id, occurred_at) WHERE
   deleted_at IS NULL`.
8. `moments` — partial index `(space_id, occurred_at, id) WHERE
   deleted_at IS NULL` (drives keyset pagination, §6); partial index
   `(created_by_user_id, id) WHERE deleted_at IS NULL`. Keep `author_role` /
   `author_name` (creation-time snapshot; never read for attribution).
9. `space_activity` — index `(space_id, occurred_at)`; check `kind ∈
   {moment_deleted, moment_edited}`. Retention = 7 days (route-level purge,
   §8).
10. `calendar_events` — partial indexes `(space_id, starts_at) WHERE
    deleted_at IS NULL`, `(created_by_user_id, id) WHERE deleted_at IS
    NULL`. Keep `recurrence`/`recurrence_group_id` (weekly-only, §7).
11. `event_proposals` — index `(space_id, status)`; check `status ∈
    {pending, accepted, declined}`; `resolved_at` retained.
12. `someday_items` — index `(space_id)`; check `category ∈ {place, food,
    film, other}`. No hard delete by design.
13. `weekly_answers` — unique `(space_id, user_id, week_key)`; index
    `(space_id, week_key)`. Question is snapshotted as `question_id`.
14. `location_shares` — unique `(user_id)` (one latest position per user);
    checks `mode ∈ {live, until_arrive, on_request_granted}`,
    `latitude BETWEEN -90 AND 90`, `longitude BETWEEN -180 AND 180`.
    Ephemeral: rows deleted outright on stop/expire/revoke — never soft.
15. `letters` — index `(space_id, sealed_until)`. Immutable post-seal;
    only the `open` transition ever writes.
16. `push_tokens` — unique `(expo_push_token)`; index `(user_id)`.
17. `oauth_states` — **unused by any route today** (grep: referenced only in
    `schema.ts`; WorkOS owns state server-side). Decision needed: drop on
    fresh D1, or keep only if Better Auth needs a state store. Default
    recommendation: drop — Better Auth brings its own storage.
18. `media_objects` — unique `(storage_key)`; index `(space_id)`;
    `upload_state ∈ {pending, complete, failed}` machine retained (§8).
19. `user_preferences` — PK `(user_id)`; theme enum check.

### 1.3 Checks and partial indexes: supported on D1

SQLite (D1) supports `CHECK`, partial indexes, and `ON CONFLICT` upserts.
All `ck_*` constraints and `WHERE deleted_at IS NULL` partial indexes carry
over verbatim. `PRAGMA foreign_keys` must be **verified pinned ON** for the
D1 connection used by Drizzle (D1 enables FK enforcement by default; make it
an explicit bootstrap assertion in the D1 layer so `ON DELETE cascade`
semantics — user delete cascades to sessions/accounts/members — hold).

### 1.4 New DB-level invariants to add on fresh D1 (do not exist on PG today)

These replace check-then-write races with constraint-enforced atomicity —
exactly the "D1 operations own atomicity via constraints" directive:

- **One active space per user**: partial unique index on
  `space_members(user_id) WHERE state = 'active'`. Replaces the two
  `existing.length > 0` guards in `routes/spaces.ts` (create + join) with a
  hard invariant; concurrent creates cannot double-activate.
- **At most one active partner per space**: partial unique index on
  `space_members(space_id) WHERE state = 'active' AND role = 'partner'`.
  Replaces the `memberCount.length >= 2` guard in join (and the 
  "this space already has two members" conflict) — two concurrent joins
  cannot both insert a partner. (Creator is always `role='you'`, so the
  invariant "≤ 1 active partner ⇒ ≤ 2 active members" holds.)
- **Invite single-redeem**: guarded `UPDATE space_invites SET
  redeemed_at = ?, redeemed_by_user_id = ? WHERE id = ? AND redeemed_at IS
  NULL` must return a row before inserting the member; wrap member-insert +
  invite-mark in one D1 `batch()` (§3.2). On conflict, respond with the
  same "already used" copy as today.
- **`push_tokens` re-registration/reassignment** already has the unique
  `expo_push_token` index + `onConflictDoUpdate` — carries over unchanged
  (device-scoped token, reassigns owner on conflict).
- **`weekly_answers` upsert** already unique `(space,user,week)` +
  `onConflictDoUpdate` — carries over.
- **`location_shares` upsert** already unique `(user_id)` +
  `onConflictDoUpdate` with `consumed_at` reset — carries over.

### 1.5 Timestamps and clocks

- Server-assigned times today: `created_at`/`updated_at` via `now()` and
  `new Date()` in handlers. On D1 keep the clock explicit: an Effect
  `Clock` layer is the single source of `now` for all writes (locked design).
  Routes that compute `now` for horizon/freshness checks (proposals, letters,
  location) must use the same injected clock so tests can freeze it.
- **Never store durable signed URLs** — retained behavior already holds:
  `media_objects` stores `storage_key`; signed URLs are minted per request
  and expire in 3600s (`routes/media.ts`).

## 2. Drizzle boundaries (D1)

### 2.1 Driver

- Replace `drizzle-orm/postgres-js` + `postgres` client
  (`src/db/index.ts`, `src/db/migrate.ts`) with `drizzle-orm/d1` bound to
  `env.DB`. Schema module is rewritten with `drizzle-orm/sqlite-core`.
- Migration runner: D1 uses `wrangler d1 migrations apply` (SQL files) or
  `drizzle-kit` with a sqlite dialect. Decide one mechanism; the 11 PG
  migrations are **not reusable** — fresh D1 means one new `0001` baseline
  SQL file generated from the new sqlite schema (all 19 tables in one
  migration, since no production PG data is being migrated).
- `DATABASE_URL` env path disappears from `db/index.ts`/`migrate.ts`;
  the D1 binding comes from the Worker env. The local-dev DB path becomes
  wrangler/miniflare D1 (or a `better-sqlite3`-backed shim for unit tests,
  §9).

### 2.2 Transaction → batch / guarded-SQL mapping

`db.transaction(...)` appears in exactly these places today; each maps to a
D1 pattern:

| Site (file:route) | Today (PG interactive tx) | D1 pattern |
|---|---|---|
| `moments.ts` PATCH (update + activity insert) | tx update + insert | `batch([update WHERE id=? AND deleted_at IS NULL, insert space_activity])` — atomic, all-or-nothing; both succeed or neither. |
| `moments.ts` DELETE (soft-delete + tombstone) | tx update + insert | same batch pattern. The guarded `WHERE deleted_at IS NULL` already prevents double-tombstone; keep it as the idempotency gate. |
| `proposals.ts` accept (status flip + event insert) | tx guarded update + insert | `batch([UPDATE event_proposals SET status='accepted', resolved_at=? WHERE id=? AND status='pending', INSERT calendar_events ...])`. The guarded update is the first-writer-wins gate; batch keeps "never accepted-with-no-event". |
| `location.ts` GET (consent re-check + row read) | tx read+read | **Single SELECT with JOIN** (`space_members` consent + `location_shares` row in one statement), or accept the documented benign race on consent revocation. Do not use `withSession` for a hot read path. |
| `auth.ts` refresh rotation (revoke old + insert new session) | sequential writes, no tx | `batch([UPDATE sessions SET revoked_at=? WHERE id=?, INSERT sessions ...])` — atomic rotation. |

Rules for the D1 layer (to state in the implementation phase):
- Multi-write atomicity = `env.DB.batch()` of **independent, pre-built
  statements** (no reads between writes).
- Cross-entity invariants that can't be one statement are enforced by
  constraints (§1.4) or idempotency gates, never by read-then-write.
- `db.delete(...)` on `location_shares`/`space_activity` (expire-purge,
  retention-purge) are single statements — no tx needed.
- `.returning()` on D1: Drizzle sqlite supports `returning()` on
  D1 (SQLite ≥ 3.35). Where a route relies on the returned row (most do),
  keep `returning()`; verify against the pinned D1 SQLite version.

### 2.3 Upserts

`onConflictDoUpdate` is used today for: push tokens, weekly answers,
location shares, user preferences (insert-else). D1/SQLite supports
`ON CONFLICT ... DO UPDATE`; the `target` column lists carry over. The
`handleOAuthUser` flow (`auth.ts`) inserts `user_preferences` with
`onConflictDoNothing` — carries over.

## 3. Effect TS boundaries

Locked design: bounded Effect TS for domain commands, typed errors, Layers,
queue/cron programs, clocks/IDs/tests. Shape constraints (from current code
shape, not from any existing Effect code — there is none yet):

### 3.1 Command surface (one Effect program per route handler body)

Each route handler today is: validate (zod) → resolve space id → guard
membership/ownership → write → serialize → fire push. In Effect terms each
becomes a program that:

- takes typed input (already validated) + `RequesterId`;
- depends on `Db` (D1) + `Clock` + `Id` + `PushQueue` layers;
- returns a **typed error union** that maps 1:1 to the existing HTTP codes
  (`BAD_REQUEST`, `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`,
  `TOO_MANY_REQUESTS`, `INTERNAL_ERROR` — see `app.ts` `httpCodeToErrorCode`);
- is run by the Hono transport adapter which translates Effect failures to
  the existing `ApiError` JSON shape `{ error: { code, message } }`.

Retained detail: the **no-existence-leak 404 pattern** (proposal of another
space, letter of another space, someday item of another space, calendar
event of another space → all `NOT_FOUND`, never `FORBIDDEN`) must be a typed
error in each command, not an ad-hoc throw.

### 3.2 Layers

- `DbLayer` — D1 binding + Drizzle client (the only place `drizzle(d1)` is
  constructed).
- `ClockLayer` — `Effect.Clock` (frozen in tests via `TestClock`); all `new
  Date()` in current handlers become `clock.currentTime` reads.
- `IdLayer` — UUID generation (replaces `crypto.randomUUID()` in
  `calendar.ts` recurrence group, `auth.ts` session ids, `media.ts`
  storage keys).
- `PushQueueLayer` — replaces direct `notifyPartnerInSpace(...)` calls:
  enqueue `{ spaceId, fromUserId, kind, fromName?, dayOfWeek? }`. The
  **payload contract is unchanged** (kind + vague copy only — `lib/push.ts`
  `buildPushCopy` must be preserved verbatim, including the calendar
  weekday-at-most rule and the location name-only rule).
- `RateLimitLayer` — Worker Rate Limiting binding (see §4.3).
- `ConfigLayer` — env secrets; fail fast with the same messages
  (`JWT_SECRET is required`, R2 creds required).

### 3.3 Queue + DLQ + Cron programs

- **Queue** (one) carries push delivery intents (the current
  `notifyPartnerInSpace` / `sendPushToUser` work — Expo batching of ≤100
  tokens, `AbortSignal.timeout(10_000)`, dead-token pruning with
  `DEAD_TOKEN_ERRORS = {DeviceNotRegistered, InvalidPushToken}`). All of
  `lib/push.ts`'s rules move into the queue consumer.
- **DLQ** for failed delivery batches; consumer must never throw unhandled.
- **Cron** jobs (fresh surface — none exist today):
  - Activity retention purge (currently inline best-effort in
    `routes/activity.ts`: 7-day window, `ACTIVITY_LIMIT = 50`).
  - Expired location-share sweep (currently best-effort inline in
    `routes/location.ts` `sweepExpiredLocationShares`; a cron makes the
    at-rest guarantee real without a GET/opt-in trigger).
  - Calendar reminder dispatch (feature exists in the app contract —
    `reminderMinutesBefore` — but no sender today; shape the cron as the
    delivery trigger, respecting "silent by default").
- Fire-and-forget semantics are preserved at the transport layer: the
  request handlers enqueue, never await Expo.

### 3.4 Test layers

Tests today mock `../../db/index.js` and `../../lib/push.js` with chainable
fakes. In Effect terms: `DbLayer` becomes a real SQLite-backed D1 test
harness (better-sqlite3 or miniflare), `ClockLayer` becomes `TestClock`
(route tests already use `vi.useFakeTimers()` + `vi.setSystemTime` for
location/letters — same intent), `PushQueueLayer` captures enqueued intents
(the current `expect(notifyPartnerInSpace).toHaveBeenCalledWith(spaceId,
userId, kind)` assertions map to queue-capture assertions).

## 4. Zod/OpenAPI contract source

### 4.1 Move schemas to `packages/shared`

Today every request/query schema is inline in the route (zod v3 + 
`@hono/zod-validator`). The fresh design moves them to `packages/shared` as
the single contract source used by: Hono validation, OpenAPI generation, and
the client (Expo app) for typed validation. Shape constraints:

- Export named schemas per surface, e.g. `createMomentSchema`,
  `listMomentsQuerySchema`, `createCalendarEventSchema` …; derive response
  types with `z.infer`. **Do not duplicate type + schema** (shared currently
  exports plain types — convert types to `z.infer<typeof X>` where a schema
  exists, keep hand-written types only for pure helpers).
- The in-progress user change `packages/shared/src/auth.ts` (`.js` import
  extension removed) is part of making shared importable by the client —
  extend that pattern to every shared module and to zod imports; no `.js`
  extensions in new shared code.
- **Error-message contract is sacred**: word-only, fixed strings. Zod
  defaults that echo numbers/bounds are explicitly overridden today
  (location `validationHook` returns one fixed `'Invalid location'`;
  proposals/letters `throwFirstIssue` surfaces the schema's own word-only
  message; calendar reminder bounds never reach the client). All schema
  messages in shared must keep this property — the client will render them.
- Constants shared today must stay shared: `WEEKLY_RECURRENCE_INSTANCE_COUNT
  = 13`, `LETTER_BODY_MAX_LENGTH = 5000`, `LETTER_CAPTION_MAX_LENGTH = 80`,
  `LETTER_SEAL_MAX_HORIZON_DAYS = 18_262`, `PROPOSAL_TITLE_MAX_LENGTH = 120`,
  `SOMEDAY_TITLE_MAX_LENGTH = 120`, `SOMEDAY_NOTE_MAX_LENGTH = 280`,
  `WEEKLY_ANSWER_MAX_LENGTH = 500`, `LOCATION_*` bounds, `PUSH_TOKEN_PLATFORMS`,
  `CALENDAR_PRESET_LABELS`, `CALENDAR_RECURRENCES`, `PROPOSAL_STATUSES`,
  `SOMEDAY_CATEGORIES`, `PUSH_NOTIFICATION_KINDS`, `LOCATION_SHARE_MODES`.
  `PUSH_TOKEN_MAX_LENGTH = 200` and the media MIME allow-lists live in the
  API today; move them to shared too (single source for client pre-check).
- OpenAPI: generate from the zod schemas (e.g. `@hono/zod-openapi` +
  `@asteasolutions/zod-to-openapi`) so `/openapi.json` derives from the same
  objects that validate. Response schemas must reflect the optional `body`
  on unopened letters (omitted key, not `null`), the `nextCursor` omission
  on last page, and `location: null` responses.

### 4.2 Behavior pinned by shared types (retained shapes)

- `Moment.isOwn`, `CalendarEvent.isOwn` — computed per request from
  `createdByUserId === viewerUserId`; the client treats missing as not-own.
- `authorRole`/`proposerRole`/`createdByRole`/`checkedByRole`/`authorRole`
  (letters) — always computed per request, never read from stored snapshot.
- Letter body lock: serializer `letterRowToApi` omits `body` unless
  `openedAt !== null` — for author and partner alike. Preserve exactly.
- Location: `PartnerLocationShare` is the only place a position becomes an
  API response; it must stay the only one.

## 6. Pagination map

- **Moments list** (`GET /v1/spaces/current/moments`): keyset on
  `(occurredAt DESC, id DESC)`, `limit ∈ [1,100]` default 20, fetch `limit+1`
  for `hasMore`, cursor = last item's `occurredAt` ISO string.
  **Constraint to fix on D1**: today the cursor carries only `occurredAt`
  and the WHERE is `lt(occurredAt, cursor)` — ties on identical
  `occurredAt` are unstable (dup/skip). The index is already
  `(space_id, occurred_at, id)`; make the cursor an **opaque composite**
  (`occurredAt|id`), filter `(occurredAt < c.occurredAt) OR (occurredAt =
  c.occurredAt AND id < c.id)` — using a bound parameter so SQLite uses the
  index. Old-format cursors (bare ISO) are client-ephemeral; decide whether
  to accept them for one page or reject with 400.
- **Calendar range** (`?from=&to=`): half-open `[from, to)` via
  `endsAt >= from AND startsAt < to`, ordered by `startsAt`, unbounded.
  Retain exactly (client contract + local repo parity).
- **Activity** (`?since=`): window = `since` clamped to 7 days back; cap 50
  newest-first; inline retention purge (moves to cron in the queue/cron
  program). Retain clamp + cap.
- **Full-list routes (no pagination)**: letters, someday, proposals,
  imported milestones, push tokens (per user). All small-by-construction;
  keep as-is on D1.

## 7. Domain invariants to retain (route-by-route)

- **Spaces**: creator-only metadata update (`createdByUserId === userId`);
  archived space = invisible to `GET /current` (`isNull(archivedAt)`).
- **Moments**: edit/delete own-only; membership re-check at write;
  tombstone `space_activity` written atomically with the mutation; activity
  kind `moment_edited`/`moment_deleted` + `subjectId` only (never content).
- **Calendar**: `endsAt > startsAt` on create **and** on merged partial
  update (recomputed from existing values); label `Other` ⇒
  `label_custom_text` required-ish (customText stored only when preset is
  Other); reminders = ints 0..2880, ≤8 entries, deduped; weekly recurrence
  expands to exactly 13 concrete instances sharing `recurrence_group_id`;
  **no series operations** — edit/delete of an instance never touches the
  group; push carries weekday-at-most.
- **Proposals**: `proposedStart > now`; `proposedEnd > proposedStart`;
  only the non-proposer may resolve; pending-only transitions; accept
  creates an event with proposer's user id + `actor` from the proposer's
  current role snapshot; label passthrough only when preset present.
- **Letters**: `sealedUntil > now` and ≤ `18_262` days out; no edit/delete
  surface at all; `readyToOpen` computed per request; open is
  `WHERE opened_at IS NULL` and only after due; second reader = idempotent
  read of the opened row; `openedByUserId` recorded.
- **Someday**: check-off/undo only meaningful transitions; no hard delete.
- **Question**: week key/question decided server-side
  (`getWeeklyQuestionForDate`); reveal gate at read time — `partnerAnswer`
  present only when both rows exist; `updatedAt` of the partner never
  surfaced.
- **Location**: both-consent gate (fast path + in-serve re-check today);
  freshness per mode (live 15 min, grant 5 min — shared
  `isLocationShareFresh` with 60s skew tolerance); one-time grants consumed
  once; ephemeral rows deleted outright; archived space hard-off; mutuality
  for requests (you can ask only if you opted in; partner must still be
  opted in at send time); 3 requests/min per sender cap.
- **Push**: token = device-scoped; reassignment on re-register by another
  user; dead-token prune scoped to the current owner; batching ≤100;
  10s timeout; silent by default (`sound: null` unless explicitly set).
- **Auth**: refresh token rotation with stored SHA-256 hash; mismatch or
  replay of a rotated token ⇒ mass-revoke all sessions of the user;
  access token 15m / refresh 30d; session rows revoked, never deleted
  (theft audit trail).
- **Media**: `upload_state` pending→complete|failed; `complete` only from
  pending; head-object ContentType must match declared MIME; EXIF strip for
  images (sharp, best-effort); presigned URLs 3600s, never stored;
  download gated on active membership + `upload_state='complete'`; filename
  sanitized for the `Content-Disposition` header.
- **Rate limits** (today, in-memory Map): global `/v1/*` 100/min per user;
  auth 10/min per IP; upload 20/min; squeeze 10/min; location request
  3/min. All move to Worker Rate Limiting bindings with the same keys
  (user id, IP, and the `squeeze:`/`location-request:` prefixed keys — the
  prefixing exists to avoid collisions in a shared store; with per-binding
  keyspaces the prefix concern mostly disappears, but the limits must not
  loosen).

## 8. Existing behavior that must be retained (cross-cutting)

1. **Error envelope**: `{ error: { code, message } }` with the exact code
   mapping in `app.ts` (400/401/403/404/409/429/500); unknown errors →
   `INTERNAL_ERROR` with a **fixed string** (never `err.message`) — request
   fragments and coordinates must never reach logs.
2. **No-existence-leak 404** pattern (cross-space resources read as 404).
3. **Per-request authorship** computed from user ids, never stored roles
   (`lib/db.ts` serializers — preserve them, only the Date conversion
   changes from `Date → toISOString()` to `number(ms) → toISOString()`).
4. **Soft-delete everywhere** for authored content (moments, events,
   imported milestones, users, media) with partial indexes; hard-delete only
   for ephemeral rows (location shares, expired sessions are revoked not
   deleted, activity purge).
5. **Push copy**: `buildPushCopy` verbatim; content never enters payloads.
6. **Privacy invariants**: coordinates never logged/echoed; letter bodies
   never leave server unopened; partner answer timing never surfaced;
   activity is fact+actor only.
7. **Calendar recurrence expansion** in the create command (13 instances,
   one group id, `crypto.randomUUID()` → `Id` layer).
8. **Graceful empty responses** when no active space: `{moments: []}`,
   `[]` (events/milestones), `{letters: []}`, `{items: []}`,
   `{proposals: []}`, `{activity: []}`, `NO_SPACE_RESPONSE` for location —
   never an error.
9. **Ownership + membership gates before every guarded write** (the
   read-then-guard pattern stays, but the guarded write is what carries the
   invariant — same as today's `WHERE status='pending'` / `WHERE
   deleted_at IS NULL` / `WHERE opened_at IS NULL` guards).

## 9. Test strategy mapping

- Current route tests are **behavioral** (mocked drizzle chains). They pin:
  response JSON shape, HTTP codes, guard-`WHERE` conditions, upsert targets,
  transaction grouping, and push kind arguments. These pins are the
  regression contract for the Effect rewrite — the implementation phase
  should port each test's assertions onto the new command surface.
- New unit strategy: Effect programs tested with `TestClock` + an
  in-process D1 (better-sqlite3 shim or `@cloudflare/vitest-pool-workers` +
  miniflare) instead of chain mocks — this is where constraint-based
  idempotency (partial unique indexes, guarded updates) gets real tests
  (double-join, double-accept, double-open, double-create-space,
  double-moment-create with idempotency key).
- Tests that specifically exercise time (`location.test.ts` fake timers +
  `isLocationShareFresh`, `letters.test.ts` `sealedUntil` horizon) map
  directly to `TestClock`.
- `crypto.test.ts`, `rate-limit.test.ts`, `validation.test.ts` port as-is
  (pure functions; rate-limit test swaps the in-memory store for the binding
  abstraction).
